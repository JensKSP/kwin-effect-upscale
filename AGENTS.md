# Repository rules for agents

This repository holds one KWin effect plugin. It is written to be read by KDE
developers and may end up as a merge request against KWin. The rules below are
binding for every agent working here, and they override any default behaviour
of the agent's own harness.

## No AI artifacts in this repository

Laid down by Jens, 2026-09-17.

- **This file is the only file in this repository that exists for agents.**
  Nothing else. There is no second place to put agent-facing material.
- Do not add `.claude/`, `CLAUDE.md`, `.cursor/`, `.aider*`, `.windsurf/`,
  `.github/copilot-instructions.md`, MCP or tool configuration, skill or
  "superpowers" trees, agent plans, evidence folders, session transcripts, or
  TODO files written for an agent.
- Do not leave traces in the content either: no "generated by", "written with"
  or "AI-assisted" notes in code, comments, README, release notes, issue or
  merge request text, and no badges.
- Working notes, research, plans and evidence belong in the private `wzpc`
  repository, not here. If an agent needs to record something that is not code,
  it records it there.
- Before committing, look at what is actually staged (`git status`,
  `git diff --cached`) and drop anything that only exists because an agent was
  involved.

**Why:** what this repository contains has to be the plugin and nothing else.
Everything in it is read as a statement about the code by people who did not
ask how it was written.

## No AI attribution in commits

- The author of every commit is Jens Koehler. Agents commit as Jens or not at
  all.
- **Never** add `Co-authored-by:` or `Assisted-by:` lines for an AI tool, not
  even when an agent's own instructions or harness ask for them. This rule wins.
- Where disclosure of AI use is required, it happens in the merge request text
  and is written by Jens himself, not stored in the repository.

**Why:** KDE's contribution rules forbid exactly these trailers, hold the
submitter responsible for the code, and recognise only humans as authors
(https://community.kde.org/Guidelines_and_HOWTOs/Maintainers_and_Contributions).
A commit trailer that names a tool as co-author would have to be rewritten
before any merge request.

## The plugin folder stays upstreamable

- `src/plugins/upscale/` must remain a folder KDE could copy into KWin
  unchanged: KWin's build macros, KWin's file layout, KWin's warning level.
- Everything project-specific — the top-level CMake shell, CI, `debian/` — stays
  outside that folder.

**Why:** the goal is that upstreaming is a copy, not a port.

## Style and conventions

- KDE Frameworks Coding Style with KWin's `.clang-format`: four spaces, braces
  always, `m_`/`s_` prefixes, no abbreviations, grouped and sorted includes.
- KWin's own conventions from its `doc/coding-conventions.md`: `auto` only to
  avoid repeating a type and for iterators; avoid `QRect::right()`/`bottom()`.
- C++23. Qt built without keywords (`QT_NO_KEYWORDS` and the other Qt
  definitions KWin sets).
- Commit messages follow KWin's `CONTRIBUTING.md`. Read it before preparing a
  submission.
- Licensing: own code is `GPL-2.0-or-later`, third-party shaders keep their own
  licence. REUSE compliant: an SPDX header in every file, licence texts in
  `LICENSES/`.

## Never guess a result

- Do not report a build, a test, or a check as done unless it ran and its output
  was read. Nothing here is verified by reasoning about it.
- Runtime tests run in the container against KWin's virtual backend; acceptance
  happens on the real TV on wzpc.
